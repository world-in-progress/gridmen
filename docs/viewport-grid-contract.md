# Viewport grid display

The patch editor and assembled-grid viewer share `TopologyLayer`. Display blocks and nodes belong to the grid-coordinate hierarchy and are independent of editable patches. Inspection and editing continue to address original cells and segmented edges.

## Hierarchy and selection

The client derives `displayLayers`, ordered finest to coarsest, from bounds, alignment origin, and native cell sizes. The server derives the same finite stored prefix with `layer_specs`. [Shared test vectors](display-hierarchy-vectors.json) fix their agreement, including native schema lattices, dyadic intermediate lattices, and coarse ancestors. Each client entry has `width`, `height`, `x0`, `y0`, `nx`, `ny`, `nativeLevel`, `xLayout`, and `yLayout`. Native levels keep their original schema numbers; intermediate levels have `nativeLevel: null`. A non-null axis layout is `[nativeParentPeriod, intervalsPerParent]`; intervals reset in each native parent and the last interval is clipped to that parent. Both implementations use half-open lattice bounds, including negative coordinates and upper bounds at the alignment origin. Original geometry is never resampled.

The last stored layer covers the grid with at most two nodes per axis. Its grid hierarchy continues implicitly: ancestor `k` doubles both dimensions `k` times, has no native level or clipped layout, and groups stored-root indices by floor division by `2^k`. Its axis range is `[floor(rootStart / 2^k), ceil(rootEnd / 2^k))`. Layer numbers continue beyond the metadata array without a storage-dependent zoom limit. These are complete grid-coordinate nodes with the same alignment origin.

The client partitions the visible grid into complete hierarchical blocks, normally no more than 128 CSS pixels along an edge. A block is one node identified by `(blockLayer, x, y)`. It ascends beyond storage roots until each visible root satisfies the circle condition, and subdivides a block only when every visible child also satisfies it. A narrow child retains its valid parent even when that parent exceeds the usual 128-pixel edge size. For each block it selects the finest `displayLayer <= blockLayer` whose projected nodes all contain an inscribed circle of radius `0.75 / min(1, DPR)` CSS pixels, including clipped last strips. All four corners of each candidate node use the existing grid-to-map projection; projection nonlinearity inside a node is ignored. At DPR ≥ 1, adjacent dyadic levels normally give 1.5–3 CSS-pixel nodes. The circle has a radius of at least 0.75 physical pixels, exceeding the square pixel-center lattice's covering radius. Ordinary center-sampled rasterization therefore lights at least one pixel in every nonempty display node, independently of subpixel placement. Field nodes have no outlines.

Original-cell widths, the fixed four-pixel transition, and the one-pixel centered outline use **CSS pixels**, matching public Mapbox projection coordinates. The selector adds the physical-pixel minimum only when DPR < 1. A 1.5–3 CSS-pixel node covers 3–6 physical pixels at DPR 2. The shader converts the one-CSS-pixel outline to drawing-buffer coverage using `canvas.width / canvas.clientWidth`. Identical CSS viewports select identical nodes and instance records at DPR ≥ 1. Tests check physical pixel-center coverage at DPR 0.5 and threshold continuity at DPR 1 and DPR 2.

An original cell at or above the selected display layer is returned and drawn in its own original bounds. A large original spanning several requested blocks has one draw instance, deduplicated by its real cell ID.

## Camera-independent summaries

Initial assembled-index construction combines nodes bottom-up once. Each node retains occupied cell area, elevation multiplied by occupied area, the full sparse class-area histogram, the finest original level, and the true smallest original cell side. Native originals supply their single class directly. Intermediate histograms are build-time temporary data; only the root histograms remain for queries above the stored prefix. Work follows stored nodes and sparse entries rather than global class count times all nodes.

Elevation is `elevationArea / occupiedArea`. Class weights use arbitrary-precision integer counts of the common finest-lattice area unit, obtained from successive native integer ratios. This preserves decimal-grid equalities and one-unit differences above the float64 integer range. Occupied and elevation totals remain physical float64 values. The class with greatest total area wins; a true equality selects the smaller code. Combining child winners is invalid: three children that are 51% B and a fourth entirely A give 61.75% A overall. Occupancy is `occupiedArea / nodeArea`, including source boundaries and holes. Summaries contain no camera weights and do not descend to leaves for partially covered screen pixels.

The editable patch index uses the same hierarchy and displays levels. Its summaries retain occupied area, minimum cell side, finest level, and selected area, with deleted and undeleted contributions. Requested ancestors above the stored prefix are built from the bounded roots. An insertion or removal updates the native node and its materialized ancestor path in O(depth). Selection uses that same index. Its changed real-cell bounds determine which visible chunks receive new identities and GPU flags; distant chunks retain their buffers. Uniform all-selected or all-unselected state is derived from the existing selection default and exceptions, so nonempty render fields need no repeated hierarchy lookup for bulk selection. General empty-node queries still return zero selected area. Cache invalidation follows the ancestor coordinates; unchanged blocks retain object identity and GPU buffers. Initial loading combines nodes bottom-up.

## Rendering and density

Geometry uploads are relative to each chunk's double-precision Mercator origin. Each instance uses sixteen float32 GPU values; source and HTTP geometry and attributes remain float64. Field color and opacity are premultiplied by occupancy once. At a fragment center, `c` is the covering node's true minimum real cell side, or the side of an original cell drawn in its own right. A refinement can darken its whole display node and must light at least one pixel.

Original cells retain fills and one-CSS-pixel centered outlines. The shader box-filters each half-width outline against the actual device pixel and combines horizontal and vertical line coverage. For a uniform square grid:

```
u = min(1, s / c)
coverage = 1 - (1 - u)^2
```

Here `s` is grid distance per CSS pixel in the same convention as the actual outline. At four CSS pixels per cell, coverage is 0.4375. The CPU helper and shader use this formula. A smooth handoff from density at four pixels to complete original outlines at eight pixels avoids a brightness jump. The real shader is tested immediately on both sides of four pixels; the difference in average darkening must be below 0.01. Attribute colors share their palette and range with the color legend. The panel explains darker density as a clue to smaller cells; formulas and renderer counters remain outside the user interface. A map-adjacent field indicator and the display panel use English and Chinese text.

## HTTP API

All routes are below `/api/grid/{node_key}/display`.

- `GET /meta` returns `revision`, `epsg`, `bounds`, `alignment_origin`, `grid_info`, `elevationRange`, and `landClasses`. Display layers are derived locally; the available attributes are level, elevation, and land class.
- `GET /nodes/{revision}/{blockLayer}/{x}/{y}/{displayLayer}` returns complete summaries at the selected layer inside that block, plus intersecting originals on coarser native layers. Both layer numbers may address implicit ancestors beyond the stored metadata prefix. The response depends only on this tuple. An outdated revision returns 409; invalid block coordinates or layer selection return 422.
- `GET /inspect?x={gridX}&y={gridY}` returns the original containing cell, its original neighbors by side, and every original segmented edge ID.

Node responses use `application/octet-stream`. The four-byte header is ASCII `GDN5`. The response length determines the record count: `(length - 4) / 72`, which must be an integer. Each 72-byte record is little-endian `<Q7dII`:

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | uint64 | True original ID; zero denotes a summary |
| `x0, y0, x1, y1` | four float64 | Grid-CRS bounds; originals retain their exact binary-file values |
| `occupiedArea` | float64 | Sum of original occupied areas |
| `elevationArea` | float64 | Sum of elevation multiplied by original area |
| `minCellSize` | float64 | True smallest contributing original side |
| `level` | uint32 | Finest contributing original schema level |
| `landClass` | uint32 | Winner of the full class-area histogram |

The client validates metadata and binary responses at their source boundaries, including exact length, finite values, occupancy, and safe integer IDs. The wire contains resolved class winners; the server retains the complete sparse histograms for aggregation. There is one reader and no former camera/viewport query route.

Summary construction validates `grid.meta.json`, `cell_topo.bin`, `edge_topo.bin`, and `ne.txt` once, using bounded Arrow/NumPy batches. Source identity uses size and modification time from one stat per file. The deterministic directory key combines the format version, source path, and that fingerprint; the revision is this key. Construction writes a temporary directory and atomically renames it into place. If another process has already published the same key, its completed directory is used. The manifest stores only runtime metadata; a benchmark obtains the cell count from the number of uint64 entries in `offsets.bin`. No cross-process build lock, pointer file, content hash, derived-file identity list, or repeated self-validation is required.

One resource directory belongs to one running service process. With the default uvicorn reload supervisor, the old worker exits before its replacement starts. Resources and their display cache share the service working directory; `cache_root()` is the single definition of `cwd/resource/.display`. At service startup, all `building-*` directories in that cache are removed, recovering partial builds left by a killed process. Two independent services sharing a resource directory are unsupported: starting one can interrupt the other's unfinished build. This startup sweep does not touch published generations and uses no lock file or process-liveness check.

Cache ownership protects an index while requests borrow it. The API, index callbacks, and resource-unmount hook import the same `gridmen_backend.display_cache` owner, including when the application starts through `src.gridmen_backend.main:app`. A build blocks only requests for the same source; queries for other sources continue. Building and resource removal occupy the same per-source operation slot. Replacement closes an index after its last request returns, then removes that source's obsolete derived generations, including previous format versions. A generation restored as current is removed from the pending-deletion set. Resource deletion drains this process's readers and removes its derived summaries. Construction publishes only a completed generation; Python exceptions, including `KeyboardInterrupt`, clean the temporary build directory. Mappings and file handles close before deletion; a permission failure remains explicit. Later opens compare only the source fingerprint, rebuilding after a change. A 409 response directly refreshes metadata and the source without entering the viewport-error channel; the old geometry is cleared during this refresh. Other loading failures release the session so Retry creates a fresh request. An inspection canceled by source replacement ends its loading state without displaying an error.

Node responses carry an ETag and `Cache-Control: public, max-age=31536000, immutable`, vary by `Accept-Encoding`, and support gzip and conditional 304 responses. The client uses ordinary browser HTTP caching; it does not access Mapbox's private `SourceCache` or add a general request scheduler. The server performs no projection, screen clipping, or camera-dependent field computation. Selected-layer lookup uses a spatial R-tree over sparse tiles. A second R-tree stores the exact rectangles and IDs of coarser native originals, so holes cannot turn coarse-tile candidates into a scan of unrelated cells. Each block performs at most two indexed lookups; selected-tile work is bounded by the viewport block, and coarse originals are processed in proportion to returned originals. Queries at implicit ancestor layers combine at most four stored roots and their complete exact class histograms, with occupancy measured against the complete ancestor node area. They require no fine-layer or original-geometry access and allocate no additional stored layers. Query cost is O(log N + output), independent of unresolved fine leaves or property-boundary complexity. Client block selection bounds requested output by the viewport.

Selected records and original binary bounds are gathered and packed in arrays. SQLite aggregates directory coordinates into one batch before Python decodes them, avoiding per-row cursor handoffs between concurrent readers. Queries retain index ownership while using its mappings and read-only spatial directory, without holding the cache dictionary lock. Record ordering is not part of the wire contract.

## Lifecycle and real topology

Mercator block selection, response decoding, and geometry preparation share one dedicated worker per source. At zero pitch and bearing, Mercator pan translates projected coordinates and zoom scales them uniformly, so exact projected lengths can be reused. Other map projections use the public four-corner projection path. The worker has one active logical request, transfers each block's buffers, and waits for its acknowledgment before sending the next input. Acknowledgments check request identity, source generation, camera usability, and editable revision. Superseded work drains to the latest view while retaining the worker's published selection; source replacement, removal, and context loss dispose it.

For each decode request, the worker validates the GDN5 body once, splits crossing originals into stable ID chunks, and prepares each field chunk and original once across that request's acknowledged blocks. Its original-ID deduplication set belongs only to that RPC. It transfers that same body and the prepared float32 buffers back without cloning the decoded cell and field object graph. The client restores one block's exact attributes before acknowledging the next input. Boundary decoding and trusted restoration share one record-construction implementation; restoration accepts only the internal validated-buffer capability and performs no second boundary validation. The wire and source attributes retain float64 precision. Editable prepare requests use the same acknowledged geometry path.

The main-thread cache stores each block together with its prepared geometry, reusing canonical original chunks by their real IDs. One set of view footprints retains the candidate, the published view, and the two most recent distinct completed stopped views, for both patch and assembled sources. Intermediate zooms cannot evict stopped views; a third stopped view replaces the oldest. The worker separately retains exact projected vertices and measurements referenced by those views' node ranges and proof corners. Spatial containment alone cannot retain a vertex: a coarse view covering the whole domain must release fine vertices belonging only to expired near views. A view is published after its geometry has been committed; readiness is announced with a final repaint after the worker acknowledgment.

Camera work retains a single in-flight view load and one latest pending camera. Public camera events coalesce into one animation frame. Movement requests and commits current visible blocks before stopping, while preserving usable data and evicting hidden GPU blocks. The single active load drains only the latest pending view; the stopped camera also receives its final update. Each draw uses the current CSS camera scale, including while network data is pending. Per-chunk minimum cell size makes mode detection independent of the number of original instances. Edits refresh immediately and reuse the current camera's block selection. Only visible blocks allocate GPU buffers, with one 64-byte instance per drawn sample and the shared palette; hidden blocks release their allocations. There is no fixed maximum-cell allocation or capacity bar.

Pitch and bearing are fixed at zero by the main map's camera controls. Display selection uses the four viewport corners, with no tilted-camera edge sampling or distance bands. Pan and zoom remain available. Original half-open bounds determine click ownership, including beside holes and across hanging edges. Assembled inspection reports real segmented edge IDs; patch inspection reports neighboring cells without invented edge IDs. Read-only inspection does not acquire edit permissions. Patch selection, deletion/recovery, storage compaction, context restoration, and the render/edit benchmark interfaces remain available. Both display modes use the shared viewport-error presentation.

The server reads final scenario cell attributes from `ne.txt` and topology from the binary files. Displaying a grid does not read `ns.txt`, assemble, resample, or prerender imagery. File and interface validation happens at boundaries; failures remain explicit. The application entry initializes one i18next instance; display text uses its `gridDisplay` namespace. Hardware performance and screenshots are separate from software WebGL correctness checks.

`npm test` runs the frontend unit suite, including the production worker. Test output goes to the terminal; temporary build files and browser profiles are cleaned up by the test tools. `npm run test:browser` discovers Chrome on PATH or in its platform installation directory; `CHROME_BIN` can name an executable. It runs the production WebGL shader and lifecycle fixture through actual animation frames in headless Chrome. Its default SwiftShader run is for correctness only. `GRID_TEST_ANGLE=metal npm run test:browser` combines `--headless=new` with `--use-angle=metal` for hardware-backed correctness checks without opening a window. Test-side observations query live GL buffers; the product retains only the field-mode indicator, without a display-statistics API. Full application performance requires a separate headless hardware campaign with an explicit DPR. Each campaign records its actual animation-frame timestamps and frequency, which depend on runtime and display configuration. Frame intervals are compared only between measurements with matching observed frequency. Node.js 22.12 or newer supplies the native WebSocket used for Chrome DevTools Protocol control.
